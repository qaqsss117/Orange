# Orange 文档与切片规范

## 1. 文档目的

本目录是 Orange 的工程事实来源。模块文档描述范围和验收，`../PROGRESS.md` 描述当前状态；代码、Issue 或口头说明与这里冲突时，必须先更新文档并记录原因。

## 2. 切片格式

每个切片必须包含：

- **目标**：一个可独立验证的用户或工程结果。
- **范围**：允许修改和必须交付的内容。
- **依赖**：前置切片 ID；没有则写“无”。
- **交付物**：代码、配置、测试、文档或构建产物。
- **验收规则**：可重复执行的通过/失败条件。
- **非目标**：防止范围扩张或误解。

切片等级：

- `G0`：安全、架构、供应链或平台门禁。
- `P0`：最小可用主链路。
- `P1`：正式发布完整度。
- `P2`：增强和渠道能力。

## 3. 状态与证据

`PROGRESS.md` 只允许以下状态：

| 状态 | 含义 |
| --- | --- |
| `not_started` | 未开始，不能声称有可用结果 |
| `in_progress` | 正在实现，必须写负责人/任务和下一检查点 |
| `blocked` | 外部条件或重复失败阻塞，必须写阻塞原因和解除条件 |
| `review` | 实现完成，等待代码/安全/产品验收 |
| `done` | 全部验收规则通过且证据已登记 |

可接受证据：CI 链接、测试报告路径、截图路径、签名产物哈希、抓包摘要、端口扫描、权限差异、真机/系统版本记录。只写“已测试”“看起来正常”不算证据。

状态按切片自身的目标和验收规则判定。前置切片尚有其他平台或发布矩阵未完成时，不能跳过本切片实际使用的接口、产物或安全边界，但也不能把与本切片验收规则无关的全局发布条件重复挂在本切片上。此类剩余条件由对应平台或发布切片继续跟踪，不阻止已有完整证据的基础切片进入 `done`。范围或契约变化使既有证据失效时，必须将 `done` 重新打开并登记原因。

## 4. 依赖主链

```text
SEC-G0
  -> ARC-G0
      -> BOOT-G0
          -> platform G0
              -> VPN-G0
                  -> API/UI/VPN P0
                      -> platform P0
                          -> P1 + release gates
```

跨模块规则：

- 所有业务 API 切片依赖 `BOOT-P0-004`，禁止单独建立直连 HTTP client。
- 所有 Data Plane 切片依赖 `VPN-G0-001` 的配置净化与 schema。
- 所有平台发布切片依赖 `SEC-G0-002` 权限白名单和 `SEC-G0-004` 供应链清单。
- 所有视觉切片使用 `UI-G0-001` 的设计 token 和 `UI-G0-002` 资产白名单。
- 所有 `done` 切片必须同步更新进度台账；发布前还要通过全局验收矩阵。

## 6. 文档变更规则

- 新增功能先新增/调整切片，再开始代码。
- 一个切片超过 5 个工程日仍无法进入 review，应拆成更小切片并保留原 ID 为父项。
- 改变安全边界、网络路径、权限、包格式或核心版本时，必须更新风险和验收规则。
- 删除切片不能直接抹除历史；在进度台账标记 `superseded` 说明替代 ID，再从活跃表移入历史区。
